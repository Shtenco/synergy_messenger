# SYNERGY Messenger V3 Phase 5 — Android Native Hardening Design

## Goal
Harden the Capacitor Android build without changing the serverless P2P security model or pretending Android can keep a WebView online indefinitely.

## Boundaries
- Official Capacitor Android scaffold must be generated by `npx cap add android`; this environment cannot currently fetch npm packages, so the repo carries an idempotent hardening overlay/apply script rather than a fake scaffold.
- `allowMixedContent` is disabled.
- Microphone capture remains user initiated.
- Foreground online window is explicitly user started/stopped. It is a process-liveness hint, not a guarantee that WebView JavaScript will execute continuously.
- Android 14 foreground-service type/permission requirements and Android 15 dataSync timeout are respected.

## Native security
Fresh Android installs use an Android Keystore AES-256-GCM plugin for Vault seal/open. The key never leaves `AndroidKeyStore`; the JS API exposes only seal/open/status/delete, not generic sign/export/private-key methods.

Existing installs with a legacy browser `vault-v1` CryptoKey do not silently switch formats. Runtime reports a migration-required state and keeps the legacy vault readable until a dedicated migration is completed.

## Android runtime bridge
A custom Capacitor plugin exposes:
- launch/deep-link/share intent payloads;
- `intentReceived` events for subsequent intents;
- explicit `startOnlineWindow()` / `stopOnlineWindow()`.

Deep links support `synergy://contact/...` and `synergy://chat/...`. Shared text is staged in the UI and is never auto-sent.

## Foreground service
`SynergyP2PService` uses `dataSync`, a visible ongoing notification and a bounded session below Android 15's six-hour limit. It contains no microphone/camera/location access and no wakelock.

## Build overlay
`scripts/apply-android-hardening.mjs` requires a real generated `android/` project, copies native sources, patches MainActivity registration and manifest entries, and fails closed if expected scaffold files are missing.

## Definition of Done
- native vault JS adapter tested
- Android intent bridge tested
- mixed content disabled
- hardening overlay contains required permissions/service/deep links/share target
- native plugin exposes no raw key/signing method
- foreground service is bounded and user-started
- browser/PWA remains functional
- Android mode fails closed if configured native security plugin is invalid
- all existing tests remain green
